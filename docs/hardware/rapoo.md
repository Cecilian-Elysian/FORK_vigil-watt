**旧观测复核**：24AE:1412 的 `GetFeature(0x08) → 02 00…` 正是该协议 feature 8 应答通道的 **ACK 0x02 = Device Busy**；HID++ ping 无响应是正常的——雷柏不是 HID++ 协议。

## 1. 状态心跳（电量的唯一来源）

dongle 每 ~3 秒自发推送 **input report 0x07（19 字节，hidraw 含 ID 视角）**，2.4G 和有线都在推：

| 字节 | 含义 |
|---|---|
| [0] | 0x07 |
| [1] | 低4位=连接方式（0=2.4G，2=有线）；高4位=sensor 类 |
| [2] | DPI 档位 0..6 |
| [3..4]/[5..6] | DPI X/Y（u16 LE） |
| [7] | **充电标志（本机实测校准 2026-10-05）：0x01=放电、0x02=充电**；充满态的值待采样（100% 时一律判充满兜底）。pedro3z0 文档此字节记为"0=有效"，与本机观测不符，以实测为准。与 mousectl 在 VT3 PRO 一代记录的 1/2 编码同族 |
| [8] | **电量 0..100**（有线=最后已知值，重插后瞬间 ~1% 属正常） |
| [9] | 背光模式 |
| [10] | 键扫率索引 |
| [11] | 轮询率码 |
| [12] | profile 索引 |
| [13..14] | USB PID（u16 LE） |
| [15] | 键/滚轮类型 |
| [16] | RF 类型 |
| [17] | sensor 模式预设 |
| [18] | bit7=RF 已连接，bit0..6=RSSI |

**电量没有查询命令**——官方驱动也是被动听心跳。充电标志已实测校准（0x01=放电/0x02=充电，见上表 [7]）；充满态的原始值待下次充满时看日志 `充电标志` 补全。

**实时更新**：`BatteryPluginBase` 认领后后台只读心跳，经 `StatusPushed` 即时 Upsert，不必等 60 秒轮询。**存活判据是该接口有没有在说话**（收到任何报文即算在线），详见下节。

## 2. 其余通道（仅备查，本应用不使用）

- EEPROM 读/写：output report 0x06，帧 `[conn, 0xA4读/0xA5写, len, addr u32 LE, payload…]`（conn：0xA5=无线/0xFF=有线），应答走 feature report 0x08（`[08, ACK, echo…, payload]`，ACK 0x01=OK/0x02=Busy）。**电量不在 EEPROM**。
- VT3 PRO 一代（1231/4431）电量查询：report 0xBA，`[conn, 0xAA, 0, addr=0]` → 应答 `[0xBA, 充电态(1放/2充), %]`。**本机 1412 实测 WriteFile 拒绝 0xBA（描述符无此 ID），二代不走这条**，勿再试。

## 3. 关键行为：鼠标停手 = dongle 静音，但**静音 ≠ 离线**（2026-10-08 修正）

鼠标停手/睡着后 dongle 不推心跳、鼠标接口也停报文，被动监听空转是**预期行为**（不是协议错/会话占死）。移动鼠标即恢复推送。

**但静音不能当离线判据**：0x07 是**活动驱动**的心跳——动鼠标时稳定 3.04s 一帧，一停手就静音，正常空档里 13~39 秒的间隙很常见（2026-10-08 实测 4 分钟内出现 5 次 >10s：13.3 / 18.2 / 26.1 / 35.3 / 39.5 秒）。旧版按"沉默 >12s → 离线"判，于是用户"鼠标一直在用"却看到掉线——只是某次 60 秒轮询（或手动刷新/改设置触发的补跑）正好撞进了空档。

### 离线判定的两条腿（现行，2026-10-08 定稿）

**① 设备自己说断链**（主判据，本次新增）

`[18].bit7` 就是"RF 已连接"。**鼠标断电瞬间 dongle 会主动吐一帧 `[18]=0x7F`**
（bit7=0 且 RSSI=127，即"断链且无信号"），随后静音 **27.9 秒**才恢复：

```
21:38:38.564  雷柏 状态帧: ... RF=0x7F(bit7连接=False RSSI=127) 原始=…7F
21:39:06.454  雷柏 状态帧: ... RF=0xD2(bit7连接=True  RSSI=82)  原始=…D2   ← 恢复
```

这条帧的价值：**设备自己告诉你断链了**，比"靠静音计时猜"精确得多。

但 `bit7` 描述的是 **2.4G 链路**，不是"设备在不在"——关机、移出范围、受干扰都会翻 0。
所以**不直接判离线**，而是走延迟确认（`RapooPlugin.Offline.Confirm = 6s`，
机制在 `BatteryPluginBase` + `OfflinePolicy`）：真关机 → 没有恢复帧 → 6 秒后翻离线；
抖动 → 3 秒后的下一帧 bit7=1 就把候选撤销了（宁可漏判不可误判）。

> 窗口 **12s → 6s** 是 2026-10-08 用户拍板的（依据：心跳间隔实测 3.04s，6s ≈ 2 个周期）。
> 真机实测的"断链帧 → 标记离线"延迟：12s 窗口下是 12.4 / 12.2 秒，6s 窗口预期 ≈ 6 秒。
> 用户提过 3 秒，被否：3s 只等于 1 个心跳周期，正常丢一帧就会误判；而且鼠标停手时 dongle
> 本来就会静音，"断链后一直没有新帧"与"停手静音"在被动路径上无法区分。

**② 接口彻底不说话**（兜底）

存活判据 = **该接口有没有在说话**：被动监听收到**任何**报文都刷新 `LastPassiveAt`
（不只 0x07；该 vendor 接口上还跑着大量 0x00/0x04/0x05 报文）。
`RapooPlugin.Offline.Silence = 90s` 是"鼠标真关机/没电"的兜底，不是主要判据。

两条判据**独立生效，谁先满足谁算**，参数都装在本插件的 `OfflinePolicy Offline` 里
（`CountPollFailures = false`——本插件零写入，轮询恒返回 null 是协议形态，不是失联）。
帧解析与链路位判定都在 `RapooCodec`（纯函数，有单测）。

> **实测（2026-10-08 21:37~21:39 会话，用户断电重连鼠标+键盘）**：雷柏 39 帧心跳、
> 最大空档 27.9s、出现 1 次 `bit7=False`，全程 `标记离线` / `重新上线` 各 **0 次**
> ——旧逻辑（12s 静音）下这两次空档必然误报。

**附带观测（未定论）**：断电重连时 `[7] 充电标志` 由 `0x01` 变成 `0x00`（电量同时 94%→95%）。
本机此前只校准过 `0x01=放电 / 0x02=充电`，`0x00` 的含义待确认——可能是"刚上电/未充电"，
也可能 [7] 根本不是纯充电标志。下次复现时留意。

## 4. 已证伪/勿再试

- HID++ ping（短/长、带/不带 ID）：雷柏无响应（非 HID++ 协议）；
- report 0xBA 电量查询（一代协议）：1412 描述符不含此 ID，WriteFile 报参数错误；
- LogitechPlugin 认领雷柏接口：已移交 RapooPlugin（`WritesEnabled=false`，纯被动零写入）。
