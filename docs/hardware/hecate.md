# HECATE 漫步者电竞（接收器 35BB:D00B）

> 从 [protocols.md](protocols.md) 拆出（2026-10-21）。结论均来自真机验证或官方软件抓包；改协议代码前先读本文。

## 1. HECATE 漫步者电竞（接收器 VID_35BB&PID_D00B）—— 贡献者真机声明，本机未复测

### 1.1 实测身份

`HECATE G5M Pro` 走 2.4G 接收器，Windows 枚举出 5 个 HID collection，其中只有厂商自定义集合可用：

| collection | usage | 长度 | 说明 |
|---|---|---|---|
| 键盘 | `0x0001/0x0006` | 21 进 / 2 出 | 系统保护，`CreateFile` 返回 `err=5` |
| 消费者控制 | `0x000C/0x0001` | 3 进 | 打不开 |
| 系统控制 | `0x0001/0x0080` | 2 进 | 打不开 |
| **厂商自定义** | **`0xFF1C/0x0092`** | **64 进 / 64 出，feature = 0** | **电量来源** |

注意 usage_page 不是常见的 `0xFF00`：按 `0xFF00` 过滤会一个接一个地漏掉本设备。

### 1.2 状态帧（report `0x04`，64 字节）

同一集合上每 1~3 秒推两类报文，二者都以 `0x04` 开头：

```
04 AA 00 AA 00 00 00 00 FF 00 …     心跳，不含电量
04 00 00 1A 00 00 00 00 XX YY 00 …  状态帧
```

状态帧字段：`[3] = 0x1A` 是帧标志，`[8] = 电量百分比`，`[9] = 充电标志`。

真机对照（2026-10-18，插 USB 线充电、官方 HECATE Connect 1.1.0.26 显示 22%）：
10 分钟内 `[8]` 由 `0x14` → `0x15` → `0x16`（20 → 21 → 22），单调上升，与官方读数一致。
充电时 `[9]` 恒为 `0x01`；同一只鼠标、同一电量 31% 时拔掉充电线，`[9]` 立刻变成 `0x00`；
2026-10-18 19:14 充满后（`[8]=0x64=100%`），`[9]` 稳定为 `0x02`（20 秒窗口内所有状态帧一致）。
**`[9]` 三态定稿：`0x00`=放电、`0x01`=充电中、`0x02`=满电**（此品牌与英菲克 `0x01=放电` 相反，不可照抄），其余取值一律 `Unknown`。

### 1.3 安全边界

插件 `HecatePlugin` 只被动读 `0x04`，不向设备写任何字节（`WritesEnabled = false`、`ProbeWrites = false`），
因此默认开启（`AppSettings.PluginEnabled["Hecate"] = true`）并参与 15 秒快发现节拍。
认领同时要求 VID `0x35BB`、PID `0xD00B` 和 usage `0xFF1C/0x0092`。探测 6 秒内没有任何报文则不认领；
只有心跳时认领为休眠，等状态帧再填电量。迈从插件按 VID 排除该接收器，避免把 64 字节厂商接口当成迈从通道。
离线判定：`Confirm = 10 秒`（状态帧 1.5~3 秒一条）、`Silence = 60 秒`，
`CountPollFailures = false`（协议没有查询命令，`PollDevice` 恒返回 `null` 是形态而非失联）。
以上帧样本来自贡献者对 G5M Pro 的抓包，本仓库维护者没有在这台机器上复测。
